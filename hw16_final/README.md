# Final_go_2024_09

Сервис реализован на алгоритме Leaky Bucket + container/heap (очередь)

Internal: Пакеты: Bucket, Group, Manager Group, ListsSystem

В пакете Bucket находятся функции управления Корзинами и очередью корзин.
Очередь корзин стандартная, на container/heap, служит управлению удалением через планировщик

В пакете Group нахадятся функции управления группой корзин, объедененных общим признаком, 
например ip, или login, количество групп может менятся. Названия и характеристики групп
изначально берутся из файла конфига config.yaml, но могут быть дополнены или изменены.
В этом же пакете находится Планировщик, удаляющий опустевшие корзины.

В пакете ListsSystem находится управление бело-черным списком исключений. Список один на каждую группу,
создается сразу вместе с группой. Хранится в памяти. Каждая запись в обшем списке носит признак isBlack, из которой становится ясно, к какому списку она принадлежит. Это дает возможность единоразовой проверки при поиске и исключает возможность быть одной записи в двух списках одновременно.

В пакете Manager Group находится Менеджер, создающий и управляющий всеми группами и бело-черным списком. Изначально данные для создания берутся из конфига. В итоге Менеджер отвечает на главный вопрос ТЗ - необходимо разрешить или запретить запрос.

Сервис реализован в http-виде. Также имеется ClI. Все хендлеры и командды cli соответствуют ТЗ
Написаны Unit-тесты. В тестах отключается постоянн, нормально текущее время и заменяется управляемой функцией.
Так же, если в конфиге выставить "is_test: true", то становятся доступны еще 2 АПИ, предназначенные для ручного тестирования. Время при этом опят же переходит в режим управляемого течения. Сдвиг времени можно задать через [PATCH] /time/add?add=1 - одна секунда, и все процессы сдвинутся на 1 секунду.
Однако в этом смысле интереснее следующая АПИ: [GET] /params/all?add=0 которая одновременно сдвигает время 
и выводит все показатели Корзин "groupsParams" и списков "specList", а также первую, предназначенную на близжайшее удаление, корзину в очереди "firstDrops"

```
"backetsParams": {
                "137.23.45.111": {                      - имя корзины
                    "id": "137.23.45.111",              - тоже имя
                    "capacity": 4,                      - емкость корзины
                    "freeCapacity": 0,                  - свободная емкость
                    "dropsSum": 4,                      - недокапанный запас в каплях
                    "leakageRate": 0.25,                - скорость капсния в каплях в сек
                    "expiry": "1990-01-02T00:00:22Z",   - время опустошения корзины
                    "deadLine": 16000000000,            - Промежуток времени до опустошения корзины
                    "priority": 0,                      - приоритет в очереди
                    "isReset": false,                   - пора удалять?
                    "isAllowed": true                   - пропустить запрос?
                }
            }
```
Посылая запросы через это АПИ с одновременным сдвигом времени представляется возможным наблюдать за всеми процессами в замедленном времени. Если необходимо застопорить время, для обоих АПИ add = 0
